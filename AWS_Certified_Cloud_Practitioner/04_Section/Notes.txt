Introduction
    IAM (Users & Groups) -> Identity and Access Management 
        Global Service
        Create User and assign to group
        When we create an account we create root User
        Create users and groups -> Groups only contain users not other groups 
        User can belong to multiple groups 

    Why do we create users and groups 
        We want to allow certain access (permissions)
        Users or Groups can be assigned JSON documents called policies 
        These policies define permissions of the users 
        In AWS we apply the least priveledge prinicple: dont give more permission that a user needs

IAM Policies 
    Policies get attached at the group level
    Users inhert access from groups 
    Inline policy is a policy only attached to the user 

    Policy Structure
        Note: * in AWS mean any/all  (Get*, List*)
        JSON documents 
            Version #
            ID 
            Statement (required)
                SID -> identifier for the statement (optioanl, "1")
                Effect: Whether the statement allow or deny access ("Allow")
                Principal: account/user/role 
                Action: List of actions this policy allows or denies
                Resource: list of resources to which the action s applied to 
                Condition: Condition on when this policy is in effect (optional)

    MFA Overview 
        Password Policy     
            Strong passwords -> higher security for your account 
            In AWS you can setup a password policy   
                Min len, lower case letter
                Change after 90 days 
                Prevent reuse 
            Multi Factor Authentication MFA
                You want to protect root account and IAM Users
                MFA = password you know + security device you own
            MFA device options in AWS 
                Virtual MFA device (Google Auth, Authy)
                Universal 2nd Factor (U2F) Security Key

    MFA Hands On 
        You download and sign up with a MFA app on your iPhone. 
        When you login to AWS you check the code on the app and then you can enter that into the AWS site and login.
        Similar to 2FA with a text just done via an app 

    AWS Access Keys, CLI and SDK 
        How can users access AWS 
            AWS Management Console (password + MFA) 
            AWS Command Line Interface (access keys)
            AWS Software Development Kit (SDK) (access keys)
        Access keys are generated through teh AWS console
        Users manage own access keys
        Access keys are secret like a password
            Access key ID ~= username 
            Secret Access Key ~= pasword 
        What is AWS CLI 
            tool that allows you to interact with AWS services using command line shell 
            direct access to public apis of aws services 
            develop scripts 
        What is the AWS SDK
            Language specific APIs (set of libraries)
            Access and manage AWS services programmatically
            Embedded within your application 
            Supports
                Javascript python ruby  Google
                Mobile SDK
            Example: AWS cli is built on AWS SDK for python

    IAM Roles for AWS Services
        Some AWS services will need to perform actions on your behalf 
        To do this we will assign permissions to AWS services with IAM Roles 
            Just like a user role 
        Ex: We may want to create an EC2 instance(virtual server)
            The EC2 instance may want to perform some action on aws 
                It needs to have permissions to do that 
                We give it an IAM Role 
        Common Roles:
            EC2 Instance Roles
            Lambda function roles 
            Cloudformation

    IAM Roles Hands on 
        A Role is a way to give AWS entities permissions to do stuff on AWS 
        We give an AWS entity a role so that it has a level of permissions to do stuff 
        
    IAM Security Tool 
        IAM Credential Report (account level)
            A report that lists all your accounts users and the status of thier various credential 
        IAM Access advisor (user-level)
            Access advisro shows the service permissions granted to a user and when those services were last accessed 
            You can use this information to revise your policies

    IAM Best Practices 
        Dont use root account except for AWS account setup 
        One physical user = One AWS user 
        Assign users to groups and assign permissions to groups 
        Create a strong password policy 
        Use and enforce the use of MFA 
        Create Roles for giving permissions to AWS services 
        Use Access keys for programmatic access (CLI/SDK)
        Audit permissions of your account using IAM Credentials Report & IAM Access Advisor 
        Never share IAM users and access keys 

    Shared Responsibility Model for IAM 
        What AWS is responsible for and what you are responsible for 
        AWS (Infra)
            Infrastructure
            Configuration
            Compliance 
        You (How you use the Infra)
            Users, Groups, Roles, Policies 
            Enable MFA 
            Rotate your keys often 
            Use IAM tools to apply proper permissions 
            Analyze access patterns & review permissions
